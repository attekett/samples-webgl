# Plan

Build a syntax-aware WebGL mutator that explores reusable state and data relationships across WebGL APIs. Start with working seeds and general changes to resource lifetime, bound state, coupled sizes, and shader structure. The [Chrome report analysis](../2026-10-15-blink-webgl-mutation-reachability.md) supplies examples of failure mechanisms, not templates or target crash signatures. Measure whether the corpus lets these operators produce clean, varied WebGL execution and visible effects.

## Scope

- In: A local WebGL mutation engine, deterministic replay metadata, browser validation, and a reviewable Grizzly adapter for the existing `browser-fuzz` harness.
- Out: Porting WebGPU or WGSL operators unchanged, embedding old report PoCs or magic values, changing the generator in `browser-fuzz`, or starting a campaign before the mutation gate passes.

## Implementation status (2026-10-15)

The valid-flow engine in [`scripts/webgl_mutator.py`](../../scripts/webgl_mutator.py) accepts one-inline-script HTML seeds and applies one to three nonoverlapping edits. The CLI defaults to one edit for diagnosis; the Grizzly batch generator defaults to three. Sidecars record hashes and byte edits for exact replay, including grouped spans for edits that change both shader stages or paired texture operations. Current operators vary draw counts and modes, viewport/scissor dimensions, vertex attribute offsets/strides, typed-array view offsets, buffer allocation sizes, texture subimage dimensions, matched texture allocation and update dimensions, buffer/texture storage repetition, and buffer reallocation after upload. State edits temporarily unbind and restore buffers, textures, framebuffers, VAOs, or programs, switch compatible buffer capture or texture upload targets, cycle a framebuffer texture attachment, retire a provably unused framebuffer or texture after its final unbind, repeat a proven program link, or move a `flush` around a draw. GLSL edits change matrix scalars, array reads, trigonometric calls, simple scalar loop bounds, and matching vertex-output/fragment-input names. The paired rename must pass `glslangValidator -l` before admission. Eligibility is conservative when resource identity or bounds cannot be proved.

The separate `grizzly-adapter-webgl-mutator` package is in `/home/attekett/git/dockerfiles/browser-fuzz/grizzly-modules/webgl-mutator/`. It generates deterministic batches, keeps source/output hashes and selection/result ledgers, records `window.__done` completion and a backstop event, and retries or terminates a stuck generator. The local runner now records completion, context loss, renderer details, and `window.__validationError`; it also handles absolute test directories.

Use `/home/attekett/git/samples-webgpu/venv/bin/python scripts/webgl_mutator.py SEED.html -n 20 -s 401 --max-edits 3 -o /tmp/webgl-mutants` to generate local samples. Add `--replay /tmp/webgl-mutants/SEED_0.mutation.json -o '/tmp/webgl-replay/%n.html'` to reproduce one output. The package's `webgl_batch_generator.py INPUT -n 200 -s 401 -o OUTPUT_DIR` is the Grizzly batch entry point.

Current local and external test suites pass. Fixed browser samples of attribute, texture, draw-mode, state, storage-order, shader, and view-offset edits completed with clean JavaScript/WebGL results in Firefox and system Chrome with ANGLE/Vulkan. The separate `--arm validation` emits one proven `bufferSubData` boundary crossing after a restricted clean prefix; the local runner recorded `INVALID_VALUE` (1281), completion, and one expected warning in both browsers. Compatible buffer and texture switches, paired texture dimensions, framebuffer and texture retirement, framebuffer attachment cycling, program relinking, and linked varying renaming passed both browsers. The paired texture edit changed the screenshot on both browsers; texture retirement kept the baseline pixels while completing cleanly. The paired varying rename was also exercised on an existing deferred-rendering seed, and attachment cycling on an existing API-coverage seed. The new [`agent_outputs/valid_buffer_texture_paired_multipass.html`](../../agent_outputs/valid_buffer_texture_paired_multipass.html) is a two-pass visual seed that makes compatible buffer and texture switching, paired texture dimensions, texture retirement, and the validation arm reachable from the corpus.

Among 417 parseable corpus HTML files before that new seed, static eligibility found 18 files for framebuffer attachment cycling and 84 for linked varying renaming. Compatible buffer switching, compatible texture update switching, and the validation arm had no eligible files, motivating the new general seed. A fixed 20-output local pilot from that seed (`-s 401 --max-edits 3`) completed cleanly in system Chrome/ANGLE/Vulkan 20/20 times and changed the baseline screenshot 12/20 times. The equal-size weighted Radamsa sample (`-m num=6,lr2=2,ld=1,ls=1,li=1,bf=1 -p od -s 401`) completed cleanly 12/20 times and changed it 6/20 times; 19/20 outputs retained parseable inline JavaScript. This is evidence for one seed and backend, not a corpus-wide rate. Historical report conditions remain excluded from operator selection.

After adding the paired texture and retirement operators, a fixed 20-output sample from the revised integrated seed (`-s 509 --max-edits 3`) completed cleanly on Chrome/ANGLE/Vulkan 20/20 times and changed the baseline screenshot 8/20 times. All three new operators appeared in that sample. Static eligibility across the current corpus is 7 seeds for framebuffer retirement, 6 for texture retirement, and 1 for paired texture dimensions. Several existing eligible seeds fail the clean-run gate before mutation, so those counts are candidates rather than proven working coverage. The earlier Radamsa result used the previous seed revision and is not a direct comparator for this sample.

The external batch generator produced five deterministic files from the revised seed; all five completed cleanly on Chrome/ANGLE/Vulkan. The validation arm still completed in Firefox and Chrome/Vulkan with the expected `INVALID_VALUE` (1281) and one browser warning per run after the seed revision.

The context detector now accepts the common `canvas.getContext('webgl2') || canvas.getContext('webgl')` fallback when both branches use the same stable canvas identifier. The three safety scanners for texture updates, framebuffer attachments, and the validation arm use the same recognition. This form occurs in 22 corpus HTML files. Two previously unreachable seeds now expose 21 VAO and 34 ping-pong texture candidates. Five single-edit VAO variants passed cleanly in both Firefox and Chrome/ANGLE/Vulkan (10 browser runs); five ping-pong variants passed cleanly in Chrome/ANGLE/Vulkan. These existing seeds do not set `window.__done`, so those runs prove clean execution but not the completion signal. The local mutator suite has 253 passing tests; the separate Grizzly package suite has 258.

Framebuffer attachment cycling now requires a standalone prior `TEXTURE_2D` bind of the same resource in the same scope, with no intervening opaque call since texture creation. This excludes uninitialized and ambiguous texture targets while retaining 18 eligible corpus files (25 candidate sites). A cycle from the integrated visual seed completed cleanly in Firefox and Chrome/ANGLE/Vulkan, with `window.__done` true and no errors or warnings. A separate WebGL1-first fallback fixture also completed cleanly in both browsers.

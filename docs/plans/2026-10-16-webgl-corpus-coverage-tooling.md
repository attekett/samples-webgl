# Plan: WebGL corpus coverage and mutation-yield tooling

2026-10-16

## Goal

Measure whether the *active* WebGL fuzzing corpus can exercise varied, valid resource-state flows with the mutators we have, then choose seeds that preserve those flows within a browser-time budget. Keep Firefox/core and Chrome/ANGLE-Vulkan extension coverage separate. An optimum is only meaningful for a declared requirement set and budget; these metrics cannot guarantee coverage of unknown driver code.

## Why the current numbers are insufficient

`scripts/feature_coverage.py` reports category presence, core API methods, and topology-connected category pairs. The full static corpus reaches 225/225 core methods and 93/93 connected pairs. The seven selected core seeds reach 52/225 methods and 33/93 pairs while exposing all 25 current valid-flow mutator families. Those numbers answer different questions, and neither proves that related calls execute in order on the same resource.

The Chrome-only `agent_outputs/mutation_vertex_buffer_state_multidraw.html` illustrates the gap. It calls `WEBGL_multi_draw`, includes zero-count draws, and replaces a buffer across small and multi-MiB sizes. The matrix has no `WEBGL_multi_draw` category, and its 225-method denominator excludes extension methods. The current mutator finds six families in this seed, with no eligible edit that directly changes the extension counts or its buffer replacement. A useful report should show the extension call, the executed state flow, and those mutation gaps separately. It should describe general buffer and attribute transitions rather than score resemblance to the historical UAF reproducer.

The WebGPU project's value classes, mutation-yield report, and corpus selector are useful patterns. Their WebGPU descriptor and device models should not be copied into WebGL. Reuse this repo's JavaScript parser, API surface, runner, and mutator metadata.

## Measurement model

Count a seed only when its canonical HTML source has an explicitly completed run in the target lane with no JavaScript, console, context-loss, or WebGL error. The normal runner's `passed` flag alone does not establish WebGL validity. Record source hash, browser binary and flags, renderer, context version, supported extensions from each seed-used context, elapsed time, and whether an intended context performed a draw. Partition extension eligibility by WebGL1/WebGL2 within each browser/backend lane; the runner's separate WebGL2 capability probe cannot determine support for a WebGL1 seed. A syntactic call, a requested but unavailable extension, or a call made only by the runner's inspection code does not count as executed coverage. Treat an unsupported extension as outside the applicable context-version denominator, and report unknown or truncated traces separately from covered requirements.

Publish four layers for each lane:

1. **Static eligibility:** core methods and overloads, extension methods, category pairs, and the mutator families and candidate sites available in each seed. Keep unresolved overloads explicitly `unknown`, including `bufferData` arguments passed through typed-array variables; classify those overloads from actual argument types in the runtime trace. Do not credit an unknown static overload as covered. Keep this layer even when a seed fails at runtime so the reason for exclusion remains visible.
2. **Executed values:** coarse argument classes, such as zero/one/positive draw counts, mixed zero and positive multi-draw counts, offset bounds, enum choices, geometric allocation-size bands, and shrink/grow/same-size replacements. Classify sizes from resolved numeric arguments or typed-array byte lengths. Do not use a particular historical driver threshold as a class boundary.
3. **Executed resource flows:** ordered operations linked by context, object identity, VAO attachment, program, and storage generation. Initial patterns cover buffer → attribute → draw → replacement → draw; attribute enable/disable and program or VAO switching around draws; texture upload → FBO attachment → render/sample; and unbind/delete/rebind after use. Credit resource consumption only when a draw has a positive vertex/index count and, for instanced draws, a positive instance count; in a multi-draw batch, credit only subdraws meeting those conditions. Retain zero-work calls as executed method and value-class evidence. Count a pattern once per seed and retain a coarse repetition class.
4. **Mutation effectiveness:** for each seed and operator family, report eligible sites, generated variants, clean completions, distinct normalized flow signatures, distinct images, total browser time, and median time. Record the sample size. Count a clean variant as productive when its flow signature or image differs from its unmutated control; retain both measures so shader edits that change only pixels and state edits that change only flows remain visible. Compute novelty per browser minute using the total campaign browser time for all launched variants, including failures, timeouts, and any required browser recovery. Median time is diagnostic and must not replace that denominator.

Define the target universe before selecting seeds. Start with WebGL core and supported extension methods from `docs/webgl_api_surface.json`, category relationships from `docs/interaction_topology.json`, and a short, reviewed list of generic resource-flow and value-class requirements. Filter core methods and overloads by their minimum WebGL version and the recorded context version; evaluate extension requirements against that context's supported extensions. A WebGL1 denominator must exclude WebGL2-only methods and overloads, even when the parent method exists in WebGL1. Context versions with no capability observation remain unmeasured. Include absent requirements in the report; a denominator built only from observed seeds hides missing flows. Keep a separate inventory view for the full corpus and a campaign view for the selected manifest. Also record the subset covered by the current, clean active controls in each lane. This measured baseline subset is the first selector's preservation requirement; the full universe remains the gap target. The initial seven core controls cannot cover all 225 core methods or all 93 connected pairs, so requirements outside the candidate pool must remain explicitly unmet rather than make selection appear to have failed.

## How the tooling would work

### Static analysis

Extend `docs/feature_categories.json` with `WEBGL_multi_draw` and connect it to draw calls, VAOs, attributes, programs, and buffer operations in `docs/interaction_topology.json`. Correct the four `WEBGL_multi_draw` arities in `scripts/extract_webidl.js` and its generated `docs/webgl_api_surface.json`, which are each one below their listed parameter counts, before using that metadata to classify calls. Preserve minimum WebGL version per core overload in the extractor and generated metadata; the existing method-level version alone cannot distinguish WebGL2 additions to a WebGL1 method. `scripts/api_audit/call_analysis.py` already records extension methods, so `scripts/feature_coverage.py` can report core and extension method denominators independently. Add a small `scripts/api_audit/value_classes.py` that uses the existing AST and constant-resolution results to classify arguments; retain an `unknown` class when an expression cannot be resolved safely. Include the API-surface hash and static analyzer version in the existing per-file cache key, alongside the category hash, so metadata or classifier changes cannot return stale fingerprints.

Normalize canonical paths before aggregating the seven core symlinks and the Chrome extension symlink. Reuse a profile only when its source hash, browser executable identity, launch flags, observed renderer, context version, and profiler/reducer version match the current lane; otherwise rerun it. The existing `--passed-only` sibling-JSON convention is insufficient for a symlinked manifest or for proving that the intended backend actually executed the seed.

### Runtime trace and flow reduction

Add an opt-in profiling mode to `webgl_test_runner.py`, with a page initialization script that observes WebGL1/WebGL2 methods and methods on objects returned by `getExtension`. Wrap calls without changing their arguments or return values. Give contexts and WebGL objects stable IDs with `WeakMap`, and retain bounded events with method, context, resource IDs, call order, argument classes, and the exact indices, targets, texture units, and uniform-location IDs needed to reconstruct state. For multi-draw, record the selected count classes and drawcount; for `bufferData`, record byte size and the bound buffer's next storage generation. Do not call `getError` inside the tracer, since that would consume an error the seed or runner may need to see.

Collect or freeze the seed trace before the runner creates its separate capability-probe context. Record the version and supported extensions of each seed-used context, rather than using the probe's WebGL2 list. Suppress trace recording around profiler-owned calls on seed contexts, including program reflection, extension inspection, and final error draining; keep those observations in separate validation metadata. Observe and preserve the seed's `getError()` return values, then drain remaining errors on its contexts after explicit completion; any nonzero result makes that run ineligible for valid-flow and value coverage. In profiling mode, await `window.__done` with a timeout, without the normal runner's fixed five-second delay or its `networkidle` navigation wait. Record navigation-to-completion time separately from capability probes and screenshots. Calibrate that cost against cases run through the actual Grizzly completion/close lifecycle before using browser minutes to rank seeds. Log a missing completion signal, context loss, a full event buffer, an observed WebGL error, or unavailable extension as an explicit measurement outcome. Keep tracing disabled for ordinary `run_tests.sh` runs; verify that profiling preserves the seed's clean result and image.

A small reducer in `scripts/api_audit/` maintains the current buffer bindings, VAO attribute pointers/enabled bits/divisors and element-array-buffer binding, program, texture bindings by unit, sampler uniform assignments, and FBO attachments per context. A `vertexAttribPointer` event records which bound buffer feeds that exact slot; each `bufferData` advances the storage generation of that buffer. Indexed draws use the element buffer held by the current VAO, with their type and offset; instanced draws use the current attribute divisors and instance count. A draw event with positive work can then identify the resources and state it consumed. Read-only program reflection can classify active attribute slots and sampler uniforms after link; track sampler locations through `getUniformLocation`, their `uniform1i` assignments, and the default texture unit zero. A bound texture counts as sampled only when an active sampler selects its unit. When reflection, identity, or control flow is ambiguous, emit `unresolved` rather than awarding a flow. This is a bounded model of the interactions the current mutators change, not a full WebGL emulator.

Track a program generation for each successful `linkProgram`. Refresh reflection, invalidate earlier uniform-location IDs, and reset sampler assignments to the default texture unit zero for the new generation. An unknown or failed link must not reuse earlier reflection to award a flow. This covers relinking already exposed by the mutator's `program_relink_duplicate` family.

Normalize flow signatures to state transitions and value classes only after reducing the exact state keys. Raw API arguments would make harmless numeric changes look like novel coverage. Keep renderer and browser identity in the result so cross-backend differences are not merged.

### Mutation-yield profiling

Use `scripts/webgl_mutator.py`'s existing source/output hashes and replay sidecars. Expose its candidate enumeration to the profiler so it can sample each eligible operator family deliberately. Generate single-edit variants for per-family attribution, then a smaller mixed-edit sample using the campaign's one-to-three-edit setting. Run each variant in the appropriate lane, compare it with its unmutated control, and save clean completion, normalized flow/image novelty, errors, and time. Keep the RNG seed, exact edit metadata, browser configuration, and sample size in a compact JSON ledger. A family with candidates but no clean flow or image change remains a reported gap; sampling uncertainty must remain visible.

### Corpus selection and report

Add one `scripts/corpus_metrics.py` entry point to combine static fingerprints, profiling ledgers, and mutator sidecars into JSON and a readable Markdown report. The report lists requirements as covered, unsupported in that lane, unresolved, or missing; shows each seed's marginal contribution; and distinguishes the full inventory from the active manifest. Keep bulk traces outside the committed report and retain hashes and summarized evidence for replay.

Select canonical seeds with deterministic weighted set cover: first preserve feature and extension calls, value classes, resource-flow patterns, and productive operator families covered by the measured active controls in that lane; then prefer seeds with higher clean novelty per calibrated campaign browser minute. Require more than one independent carrier for important flows when the candidate pool has them. Do not let a symlink or a second copy of the same source satisfy that redundancy. Report the exact unmet full-universe requirements and any baseline-preservation failures at each seed/time cap. If a cap cannot fit the preservation subset, report that no qualifying manifest exists at that cap. A greedy selector using the standard library is sufficient initially; validate its decisions by comparing equal-time campaigns rather than calling its output a global mathematical optimum.

The first selector considers only the seven profiled core controls in each browser lane and the profiled extension control in Chrome/ANGLE-Vulkan. The full corpus remains a static inventory, with unprofiled seeds labeled `unmeasured` rather than treated as failed or eligible for selection. Admit another canonical source only after it has an explicit completion signal and passes control profiling in every lane where it may be selected; then rerun selection with that expanded candidate pool.

## Implementation order and acceptance checks

1. Correct the four multi-draw arities in the extractor and generated metadata, preserve minimum WebGL version per core overload, then add the extension category, context-version denominators, canonical path handling, and value classes. Assert that each `WEBGL_multi_draw` arity matches its parameter count; test the six-argument `multiDrawArraysWEBGL` call, zero and positive counts, typed-array sizes, unresolved expressions, and extension requested versus called. Test a WebGL1-only denominator that excludes `createVertexArray`, `drawArraysInstanced`, and the WebGL2 source-offset overload of `bufferData`. Test that `bufferData` with a typed-array variable stays unknown statically and is classified as a data upload at runtime. Test that a change to the API surface or static analyzer invalidates a cached fingerprint.
2. Add opt-in tracing and program/resource IDs to the runner. Test that the runner's probe, profiler reflection, extension inspection, and final error-drain calls are excluded from seed-executed coverage, WebGL1 and WebGL2 extension support comes from the seed-used context, extension methods are captured, return values survive wrapping, a seed-consumed WebGL error still fails validity, remaining errors are drained after completion, an event cap is reported rather than silently dropping coverage, and changed browser flags or profiler version invalidate a saved profile.
3. Add the flow reducer with fixtures for the same buffer through draw/reallocation/draw, different buffers with the same API names, distinct positive attribute indices, inactive versus unknown program slots, VAO changes, different element buffers held by VAOs during `drawElements`, changed attribute divisors during instanced draws, sampler assignments across texture units, a rendered texture bound only to an unused unit, unexecuted branches, and repeated loops. An unrelated resource, unused texture, unexecuted call, zero-count draw, zero-instance draw, or all-zero multi-draw batch must not satisfy a resource-consumption pattern; a mixed multi-draw batch credits only its positive subdraws.
   Test successful relinking after a sampler selects unit one: a subsequent draw must use the reset unit zero and refreshed reflection, and earlier location IDs must be invalid. Failed or unknown links must not reuse stale reflection for coverage credit.
4. Add deterministic per-family profiling and replay checks, including a clean shader edit that changes pixels without changing a flow signature. Test that a slow timeout increases the total browser-time denominator and lowers novelty per minute even when median time stays unchanged. Reuse `scripts/tests/test_webgl_mutator.py` and `scripts/tests/test_webgl_runner.py`; add focused reducer and report tests under `scripts/api_audit/tests/` and `scripts/tests/`.
5. Run the seven core controls on Firefox and Chrome/ANGLE-Vulkan and the extension control on Chrome/ANGLE-Vulkan. Verify clean completion, renderer and extension records, at least one intended positive-work draw, and the same visual result with profiling enabled. Use small fixed mutation samples to check all 25 families are represented or explicitly reported as gaps.
6. Define the measured baseline subset and calibrate profiler navigation-to-completion time against Grizzly case time in each lane. Generate a proposed manifest from the profiled candidate pool and compare it with today's baseline for equal campaign browser time, using the same browser binaries, flags, mutator settings, and RNG seeds. Adopt it only after the new report preserves the measured baseline requirements and its clean, flow-distinct and image-distinct mutation yields are each at least as strong. Record full-universe gaps, any tradeoff, and unmeasured requirements in the selection report.

The first release is successful when the Chrome extension seed is correctly credited for an executed `WEBGL_multi_draw` call and its general resource flows, while the report still exposes its currently unreachable mutation sites. That distinction is the reason for this tooling: it lets corpus changes target missing *mechanisms* without repeating one known bug's conditions.
